# 脉冲 Pulse：Ubuntu 桌面资源监控工具

这一版定位为轻巧、清晰、适合常驻的本地桌面工具。打开能看到整机负载，继续点击即可找到占用资源的进程，或者查询某个端口对应的服务。

当前交付是设计方案和交互原型。全部硬件型号、数值、进程、端口均为示例，不代表你的电脑；没有采集本机信息、结束进程或修改系统。浏览器预览用于评审布局与操作流程，实际产品采用原生 Qt。

## 1. 推荐的视觉方向

| 方向 | 视觉特征 | 适用理由 |
|---|---|---|
| **A · 暖色深色极简，主推荐** | 石墨灰底、暖橙重点色、16px 左右圆角、克制的细边框 | 长时间观察图表比较舒适，表格与数据的层级清楚，也能呼应 Ubuntu 的暖色气质 |
| B · 浅色 Fluent | 浅灰侧栏、白色卡片、同一套圆角和暖橙重点色 | 日间办公更清爽，与深色方案共用布局和组件 |

已经把 A 做成完整的三个核心页面，并补充同布局的浅色主题效果。其他专业风格也可继续调整。

### 视觉规范

- 桌面预览窗口为 **1024 × 700**，左侧导航 176px。原生版本窗口可缩放，内容不足时滚动。
- 主背景 `#17191E`；侧栏 `#1C1E24`；卡片 `#20232A`；边框 `#30333C`。
- 主文字 `#F1F0F3`；辅助文字 `#A2A6B2`；重点色 `#F3987E`。
- CPU 使用暖橙，内存使用薄荷绿，GPU 使用柔紫，网络使用浅蓝。颜色同时配合名称、数值、单位，避免单靠颜色传达信息。
- 窗口圆角 17px；卡片 12–13px；按钮和输入框 8–9px。采用 4/8px 间距体系，页面边距 24px。
- 界面字体使用 Ubuntu / Noto Sans CJK SC / 系统无衬线。PID、地址、端口使用等宽字体；数字使用等宽数字。
- 只在数值更新、切换和悬停时使用短动画。支持减少动态效果偏好。没有持续发光或大面积模糊背景。

## 2. 功能与页面

### 资源总览

首屏回答“电脑现在哪里忙”。上方四张卡片显示 CPU、物理内存、GPU 和网络；中央显示可切换的趋势图和 GPU 面板；下方显示 CPU 占用前三进程与磁盘状态。

| 模块 | 首屏信息 | 后续扩展 |
|---|---|---|
| CPU | 整体利用率、线程数、温度、频率、趋势 | 每核/逻辑线程、负载均值、iowait |
| 内存 | 已用、总量、可用量、趋势 | swap、缓存、应用内存构成 |
| GPU | **计算利用率与显存占用分别展示**，温度、功耗、风扇 | 多 GPU 切换、编码/解码引擎 |
| 网络 | 指定网卡下载/上传速率 | 网卡切换、累计流量 |
| 磁盘 | 分区容量、读取/写入吞吐量 | 多盘、IOPS、繁忙率 |

点击资源卡片切换曲线；支持 1、5、15 分钟范围和悬停读数。首版使用单资源曲线，避免多条曲线叠加后难以辨认。

### 进程洞察

首屏回答“哪个进程最吃资源”。左侧主表格、右侧固定详情卡。每个进程保留原始名称，同时展示中文用途描述，例如“模型训练”“浏览器”“桌面合成器”；PID 在名称旁显示。支持进程名、中文描述、PID、命令搜索；CPU、内存和显存排序；全部、我的、使用 GPU 三种范围。

详情卡同步展示中文用途、启动命令、用户、PID、状态与资源数据，提供复制 PID 和关联端口入口。结束进程先展示进程名、PID 和命令的确认框。实际执行前重新验证 PID 与创建时间，避免 PID 被复用后误操作；先发送 SIGTERM，强制结束是独立的后续操作。预览的结束按钮仅演示确认流程。

原生版本的中文描述优先来自应用元数据和可维护的进程映射。Python、Node 等通用运行时只在命令行有明确线索时补充具体用途；未识别项显示“用途待识别”，避免仅凭名称猜测。导出数据保留原始进程名和中文描述。

**统计口径：**首版进程 CPU 默认按整机总算力归一化到 0–100%，与总览一致；可后续提供 Linux top 风格的单核 100% 模式。表格内存为 RSS，不能把所有进程的 RSS 简单相加当作系统内存占用；共享页会重复计数。

### 端口查询

首屏回答“3000 被谁占用了”。支持端口、协议、地址、进程和 PID 查询；提供 TCP/UDP、回环地址/所有网卡筛选。点击一行展示绑定地址和所属进程，再跳转到进程详情。

TCP 使用 LISTEN 表示监听状态；UDP 显示绑定端点，不伪称 TCP 监听状态。所有网卡绑定仅说明地址范围，外部能否访问还取决于路由与防火墙。权限不足、进程已退出、无匹配结果均有明确状态；受限 PID 不显示成零或“空闲”。

### 偏好设置

刷新间隔 1–5 秒、亮/暗主题、数值变化提示、关闭后驻留托盘。托盘依赖桌面环境支持，原生开发时检测能力。预览提供按钮、搜索、下拉框、标签页、滑块、复选框、单选框与禁用状态的交互展示；设置不跨浏览器刷新保存。

## 3. UI 组件与技术方案

**建议：Python + PySide6 + QFluentWidgets（PySide6 版本）+ pyqtgraph。** QFluentWidgets 作为你要求的 UI 组件库，承担导航、输入、按钮、消息提示和设置控件；图表使用 pyqtgraph；硬件采集放到独立工作线程。预览是按这套组件思路制作的 HTML 设计稿，还没有安装这些原生组件。

| 层 | 建议实现 | 目的 |
|---|---|---|
| 主窗口 | PySide6 / QWidget、QMainWindow、QStackedWidget | 原生桌面程序、页面切换、键盘支持 |
| UI 组件库 | QFluentWidgets，选择 PySide6 对应发行包 | 圆润控件、导航、设置卡片、提示框 |
| 表格 | QAbstractTableModel + QSortFilterProxyModel + Delegate | 大量进程时保持排序、搜索和滚动流畅 |
| 曲线 | pyqtgraph + 内存环形缓冲区 | 低成本增量更新，避免不断重建图表 |
| 系统采集 | psutil 与 Linux 系统接口 | CPU、内存、磁盘、网卡、进程、连接 |
| NVIDIA GPU | NVML，按运行环境支持的指标采集 | GPU 利用率、显存、温度、功耗与进程显存 |
| 其他 GPU | 独立 AMD / Intel 适配器，按硬件和驱动验证 | 逐项声明能力；不可用项显示“未支持” |
| 打包 | 优先 `.deb`，开发期独立虚拟环境 | Ubuntu 安装、桌面入口、图标、卸载 |

使用 QWidget 的 QSS 风格与局部绘制实现当前视觉。`pulse-dark.qss` 提供完整的基础控件主题；QFluentWidgets 的自绘控件需使用其主题 API 和局部定制，不能假设全局 QSS 可以覆盖所有绘制。曲线和环形图的颜色需在绘图代码中单独配置。

Ubuntu 首版优先保留系统窗口管理能力；圆角内容区与标题栏按图稿实现。Wayland 与 X11 的窗口拖动、缩放、圆角和阴影需要分别验证；如无边框窗口适配有问题，保留系统装饰也能使用同一套内部 UI。模糊透明效果不作为必需依赖。

QFluentWidgets 项目列有 Linux 与 PySide6 支持；其公开 README 对非商用与商用授权有区分，项目实际发布前按用途核对该库的当前许可。这是组件选型事项，不影响当前设计评审。

## 4. 数据与性能策略

- UI 线程只处理显示。后台采样通过信号传递不可变快照，不在界面线程执行阻塞式硬件查询。
- 默认硬件和进程采样周期 1 秒，端口 3–5 秒或手动刷新；原生代码以单调时钟计算时间差，磁盘和网络吞吐量由计数器差值得到。
- CPU 使用连续两次采样差分，首次采样显示“采样中”；按 `(PID, create_time)` 追踪进程。退出、拒绝访问与僵尸进程均可容错。
- 内存以 `total - available` 表示已用，并注明口径；单位统一为 GiB/MiB、MiB/s/KiB/s，避免十进制 GB 与二进制 GiB 混用。
- 15 分钟、1 秒粒度的每条曲线保留 900 个样本；展示时按像素做降采样，缩小后保留峰值。
- 暂停后保留最后快照并显示暂停状态；恢复时重置必要的差分基线，不把整个暂停时段误当作 1 秒。
- 缺少 GPU、驱动不支持、温度传感器不可读和权限不足均显示原因。第一阶段不承诺所有显卡都有相同指标。
- 性能目标先以常规桌面场景中的低开销为准，验证后给出 CPU、内存与采样耗时实测；不把未经测量的“低于 1%”写成保证。

## 5. 实施计划与验收

| 阶段 | 交付内容 | 验收点 |
|---|---|---|
| 0 · 设计评审，当前 | 三页交互原型、深浅主题效果、QSS 基础主题、本文档 | 页面信息清楚、圆角与配色符合偏好、关键跳转可演示 |
| 1 · 原生 UI 骨架 | PySide6 主窗口、QFluentWidgets 组件、三页导航、模拟数据模型 | 布局接近设计稿，键盘可操作，缩放无重叠 |
| 2 · 系统指标 | CPU、内存、磁盘、网络、NVIDIA 适配器、趋势缓存 | 与系统工具在相同统计口径下对照；无设备和权限状态正确 |
| 3 · 进程与端口 | 搜索、排序、详情、关联跳转、真实确认操作、导出 | 进程退出不崩溃，排序稳定；指定测试服务可正确反查 PID |
| 4 · Ubuntu 打磨 | Wayland/X11、HiDPI、主题、桌面入口、打包、托盘能力检测 | 安装卸载可用，长时间运行稳定，记录性能开销 |

首版聚焦你提出的资源监控、进程排行和端口定位。告警阈值、历史记录、悬浮迷你窗和 AMD/Intel 深度指标适配在核心流程稳定后逐步增加。实际硬件、Ubuntu 版本和分发方式确定后，再细化工期。

## 7. 选型依据

- [Qt for Python 官方文档](https://doc.qt.io/qtforpython-6/)：PySide6 与 Qt 模块。
- [QFluentWidgets 官方项目](https://github.com/zhiyiYo/PyQt-Fluent-Widgets)：Qt 组件、Python 绑定版本、平台说明与授权说明。
- [pyqtgraph 官方文档](https://pyqtgraph.readthedocs.io/en/latest/)：支持 PyQt / PySide 的绘图库。
- [psutil 官方文档](https://psutil.io/)：系统和进程资源采集。
- [NVIDIA NVML 官方文档](https://docs.nvidia.com/deploy/nvml-api/latest/index.html)：GPU 管理与监控接口。

设计使用你指定的 design 与 qt-ui-designer 技能，结合深色风格与 Bento 布局参考，并针对 Ubuntu 监控场景调整为低饱和配色。
